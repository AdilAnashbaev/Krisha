# Krisha Watcher — приложение для поиска домов

Ежедневно сканирует krisha.kz (продажа домов, Медеуский р-н и «горные»
микрорайоны Алматы) и показывает в Telegram Mini App только те дома,
что подходят под все критерии:

- 5–6 комнат
- 100–140 млн ₸
- есть фото
- свежий ремонт
- 1 этаж
- центральные отопление, водоснабжение, канализация
- расположение «выше» пересечения Абая/Достык — либо по списку
  микрорайонов (Коктобе, Горный Гигант, Каменское плато, Тау Самал,
  Алатау/ИЯФ, Бутаковка и т.п.), либо по координатам южнее этой точки

При появлении новых подходящих домов бот сам пришлёт сообщение в Telegram.

## Как это устроено

```
scraper.py     — скрипт, который ходит на krisha.kz и фильтрует объявления
config.json    — все критерии поиска (можно менять без знания кода)
data/          — результаты последнего запуска (listings.json, seen_ids.json)
index.html     — само мини-приложение (открывается в Telegram)
.github/workflows/daily-scan.yml — расписание: запускает scraper.py каждый день
```

Скрипт работает бесплатно на GitHub Actions — по тому же принципу, что и
твой fitness-трекер (GitHub Pages + бот), просто здесь добавлена
ежедневная фоновая задача, которая сама обновляет данные.

## Настройка (один раз)

### 1. Создать репозиторий на GitHub
Создай новый **приватный** репозиторий (например `krisha-watcher`) и
залей туда все файлы из этого архива.

Приватный — потому что твои критерии поиска (в т.ч. бюджет) не должны
быть публичными.

### 2. Включить GitHub Pages
Settings → Pages → Source: `Deploy from a branch` → ветка `main`, папка `/ (root)`.
После сохранения GitHub даст ссылку вида
`https://<твой-логин>.github.io/krisha-watcher/` — это и есть твоё
мини-приложение.

> Для приватного репозитория GitHub Pages доступен на платных тарифах
> GitHub Pro/Team. Если репозиторий должен остаться приватным и бесплатным —
> напиши, соберу альтернативный вариант хостинга (например, Cloudflare Pages
> с деплоем из приватного репо).

### 3. Создать Telegram-бота (если ещё нет отдельного под это)
Через `@BotFather`:
- `/newbot` → получишь `BOT_TOKEN`
- `/setmenubutton` (или в настройках бота) → укажи URL из шага 2 — так
  бот откроет мини-приложение по кнопке в чате

### 4. Узнать свой chat_id
Напиши что-нибудь своему боту, затем открой в браузере:
`https://api.telegram.org/bot<BOT_TOKEN>/getUpdates`
и найди `"chat":{"id": ...}` — это и есть `CHAT_ID`.

### 5. Добавить секреты в репозиторий
Settings → Secrets and variables → Actions → New repository secret:
- `TELEGRAM_BOT_TOKEN` = токен бота
- `TELEGRAM_CHAT_ID` = твой chat_id

Без этих двух секретов приложение всё равно будет работать и обновляться —
просто не будет присылать уведомления, придётся заходить и смотреть самому.

### 6. Проверить вручную
Actions → Daily Krisha scan → Run workflow — запустит скрипт прямо сейчас,
не дожидаясь расписания (по умолчанию расписание — 08:00 по Алматы).
Посмотри в логах, сколько объявлений найдено и сколько отсеялось на каждом
критерии.

## Важные оговорки

- **У krisha.kz нет официального API и нет фильтра «выше Абая/Достык»** —
  я сделал скрипт по видимой структуре сайта и логике текста объявлений
  (регулярки + разбор HTML), но не тестировал его на живом сайте из этого
  диалога — у меня нет прямого доступа для боевого прогона. Довольно
  вероятно, что после первого реального запуска что-то придётся
  подправить (например, если поменяется вёрстка карточки или названия
  полей в характеристиках). Логи в Actions покажут, на каком именно
  критерии отсеиваются объявления — это главная точка отладки.
- Критерий «центральное водоснабжение» отдельного чекбокс-фильтра на
  сайте не имеет (у домов чаще пишут «поливная вода»), поэтому скрипт
  ищет эту фразу в тексте объявления — если продавец не указал явно,
  подходящий дом может быть пропущен.
- Гео-фильтр «выше Абая/Достык» — это эвристика (список микрорайонов +
  координаты из страницы объявления, если их удаётся извлечь), а не
  точная граница. Список микрорайонов и широту-порог можно
  скорректировать в `config.json` (`mkr_allowlist`, `geo_boundary_lat`,
  `geo_filter_mode`).
- Сайт защищён от автоматических обращений (капча, возможные
  ограничения по частоте запросов). Скрипт делает паузы между запросами
  и запускается всего раз в день, но если запросов станет слишком много —
  сайт может начать отдавать капчу вместо страницы. Если увидишь в логах
  много `HTTP 403`/пустых страниц подряд — дай знать, снижу частоту или
  добавлю ротацию заголовков.
- Все критерии редактируются в `config.json` без изменения кода:
  бюджет, комнатность, список районов/микрорайонов, включение/выключение
  отдельных требований (например, если захочешь на время снять
  требование «1 этаж»).

## Локальный запуск (для проверки)

```bash
pip install -r requirements.txt
python scraper.py
```

Результат появится в `data/listings.json`, а `index.html` можно открыть
локально (`python -m http.server` в этой папке) — он читает
`data/listings.json` по относительному пути.
